

# SpendWisely 🪙

A full-stack, gamified personal finance dashboard designed to track transactions, visualize spending habits, and reward users for smart financial management. 

I built this project to bridge the gap between heavy backend data processing (using Python and SQL) and building a highly interactive, premium frontend experience. 

## 📖 The Development Journey

When I started mapping out SpendWisely, I wanted to avoid relying on plug-and-play UI libraries (like Material UI or AG-Grid) and instead challenge myself to build core components from scratch. Here is a look at how this application came together:

* **Phase 1: The Data Foundation:** I started by designing the PostgreSQL schema and seeding it with 10,000+ realistic transaction records. Given my background in data analytics, I wanted to make sure the server could handle heavy queries, so I implemented server-side pagination, sorting, and dynamic filtering using a `WHERE 1=1` query generator in FastAPI.

## Database Setup
1. Create a `.env` file and add your PostgreSQL 18 URL: `DATABASE_URL="your_neon_url_here"`
2. Install dependencies: `pip install psycopg2-binary python-dotenv`
3. Run the seed script: `python seed.py`

* **Phase 2: Bulletproof Transactions:** The gamified rewards system was the trickiest backend challenge. I needed to ensure that if a user double-clicked the "Redeem" button, they wouldn't get a negative coin balance. I solved this by implementing strict ACID-compliant database transactions using `SELECT ... FOR UPDATE` row-level locks. 

* **Phase 3: The Dashboard UI:** I shifted to React and Tailwind CSS to build the frontend. I went for a dark-mode, glassmorphism "bento box" aesthetic. The custom data table was built entirely from scratch to handle the server-side paginated data seamlessly.

* **Phase 4: Bringing Data to Life:** Finally, I integrated Recharts to build dynamic pie charts that instantly recalculate and redraw themselves whenever the user filters the transaction table by category, date, or amount.

## 🚀 Key Features

* **Gamified Rewards System:** Users earn "Coins" (CP) through their financial activity, which can be redeemed for real-world rewards.
* **Atomic Redemptions:** Protected by strict PostgreSQL row-level locks, ensuring zero race conditions even under heavy concurrent loads.
* **Server-Side Processing:** Highly efficient server-side logic handling dynamic filtering (by merchant, category, status, and amount) over large datasets.
* **Custom UI & Data Table:** Built from the ground up using Tailwind CSS, featuring a premium dark-mode aesthetic, frosted glass effects, and a custom-built data table.
* **Interactive Analytics:** Dynamic business intelligence visualizations that update in real-time based on active search parameters.

*   ✅ **Server-side processing:** Pagination, sorting, and dynamic combined filtering (search, category, status, amount, and date ranges).
*   ✅ **Spend analytics:** A responsive chart that updates based on the actively filtered dataset.
*   ✅ **Rewards catalogue:** A working redemption flow with a visible coin balance.
*   ✅ **Strict backend validation:** Preventing unaffordable redemptions, protected by PostgreSQL row-level locks.
*   ✅ **Custom row-click modal:** Built from scratch with an Escape-key close functionality.
*   ✅ **One-command seed script** for the PostgreSQL database.

**What is Not Done (Skipped for Time/Scope):**
*   ❌ **Chart-to-Table Cross-Filtering:** The table filters the chart perfectly, but clicking a slice on the pie chart does not currently apply a category filter back to the table.
*   ❌ **Authentication:** The app uses a mocked "logged-in" state (User ID 1) to fulfill the transaction requirements within scope.

## 🤖 AI Usage Disclosure

In the spirit of full transparency regarding the development process, AI tools were utilized to accelerate specific parts of this build:

*   **Gemini:** Utilized to generate the initial foundational logic for complex frontend components (such as structuring the React state for the `FilterBar`) and troubleshooting difficult state-management bugs. I also used Gemini to help draft the initial SQL schema for the PostgreSQL tables.
*   **VS Code Copilot:** Used as an inline assistant to speed up UI development and suggest Tailwind CSS classes. It is important to note that the UI was not strictly generated by AI; Copilot was used to autocomplete tedious markup while I actively guided the layout, custom ternary logic for themes, and overall component architecture.
